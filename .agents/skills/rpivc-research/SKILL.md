# RPIVC Research

Produce current-code research, not a design. The invoked skill content is already loaded; do not reread `SKILL.md` with a shell command. Run the deterministic input preflight as the first command. After it succeeds, read [the research contract](references/research-contract.md) and [the research template](assets/research-template.md) completely before preparing the tracer card.

## Preflight the research input

Require exactly one input: either a non-empty free-text research prompt or one manually supplied absolute path beneath `.rpiv-codex/artifacts/discover/`. Pass the complete input as one literal process argument to `node .agents/skills/_shared/scripts/artifact-check.mjs preflight-research <input>` before any target-source inspection. Do not interpolate it through shell evaluation. Do not `cat`, read, or combine the discovery artifact or target files in any earlier command; discovery `artifact_content` comes from preflight. This single safe command classifies the input and captures current repository context.

- In `prompt` mode, use `research_prompt` verbatim as the authoritative scope. There are no inherited discovery facts, decisions, deferrals, acceptance criteria, or open questions. Do not request a discovery artifact.
- In `discovery` mode, read the emitted `artifact_content` completely. Reject a missing, malformed, non-discovery, incomplete, relative, or out-of-repository artifact. If its repository context differs from the current checkout, present changed fields and ask **Refresh evidence**, **Continue with the disclosed stale boundary**, or **Stop**. Write nothing and inspect no target source before this decision.
- Treat a path-shaped input as an artifact attempt. Never silently reinterpret an invalid artifact path as free text.

Only in discovery mode, inherit the discovery problem, users, goals, non-goals, success criteria, recommended approach, decisions, corrections, cross-cutting requirements, explicit deferrals, open questions, citations, and evidence gaps. Do not re-interview the user about settled discovery facts.

## Gate scope tracing

Prepare one complete `rpivc-scope-tracer` YAML card using the contract schema. Its `inputs` must identify the mode and include either the exact direct prompt or the absolute validated discovery artifact plus inherited facts. Include the repository snapshot, explicit model and reasoning, behavioral read/search/Git-read permissions, budgets, evidence schema, and stop condition. The card uses the literal field `reasoning: medium`; `reasoning_effort` is a spawn-API argument and is forbidden as a displayed card field. Display it and ask **Run**, **Edit**, **Omit**, or **Stop**. End the turn and run nothing.

Copy `repository`, `branch`, `commit`, and `working_tree_sha256` literally from the one authoritative preflight or refreshed context snapshot. Never recompute an alternative hash from Git file names or status output. Before display, pass the complete card on standard input to `node .agents/skills/_shared/scripts/artifact-check.mjs validate-research-card` with a quoted heredoc. This validator compares the card to the current repository snapshot, enforces the role profile, requires exactly one 64-character `working_tree_sha256` and one `reasoning`, and rejects `reasoning_effort`. A failed card is not approvable; correct it and validate again before displaying the gate.

- **Run** authorizes only the latest displayed card.
- **Edit** produces a complete revised card and another gate.
- **Omit** runs no tracer; continue only if the user supplies 5–9 replacement questions meeting the contract.
- **Stop** ends without an artifact.

Immediately before every authorized spawn, pass the exact transport envelope through `validate-research-card` again, then reuse those validated bytes as the child `message`. Never retype or reconstruct a card between dispatch-time validation and the spawn call.

Refresh repository context immediately before dispatch. Any change requires a refreshed card and a new **Run**. The tracer always uses `dispatch_mode: spawn`. Pass the approved card envelope as the only message and inherit no conversation. With the named-task `spawn_agent` schema, set `agent_type` from `role`, exact `task_name`, `fork_turns: "none"`, exact `model`, and `reasoning_effort` from `reasoning`. With the deferred `multi_agent_v1__spawn_agent` schema, set the same explicit `agent_type`, `model`, and `reasoning_effort`, map no inherited conversation to `fork_context: false`, and keep `task_name` inside the approved envelope because that schema has no task-name parameter. These are equivalent no-history dispatches; never omit or set `fork_context: true`. After spawning, wait for that authorized child to reach a final status and use its returned payload before ending the turn; never return an “awaiting child” placeholder as the tracer result. If the available runtime cannot explicitly request the role, model, reasoning, and no-history context, stop and report the card unverified; do not rely on a project-agent default as proof of the approved request. Children must not spawn children or write files.

After tracing, require and show the five tracer sections **Discovery Summary**, **Research Questions**, **Shared Files**, **Evidence Gaps**, and **Proposed Execution Plan**. Before offering the checkpoint, pass the complete tracer payload on standard input to `node .agents/skills/_shared/scripts/artifact-check.mjs validate-research-scope` with a quoted heredoc. The result is incomplete unless validation confirms 5–9 contiguous numbered unanswered questions, at least three existing in-repository artifact citations per question with exact labels and bounded lines, and exact question coverage across no more than three proposed groups with a specialist named for each. Every tracer citation must use a full repository-relative `path:line` label and a literal absolute local target beginning with `/`; `file://` targets, basename labels, nonexistent targets, out-of-bounds lines, and targets without a line or range are invalid. Never substitute, summarize, or parent-author questions, citations, or a plan for an incomplete tracer payload. If the tracer payload is invalid, report the validator error and stop without **Use scope**, analysis cards, or dispatch; the four-child ceiling leaves no implicit tracer-retry slot. Consolidate related work before presenting the checkpoint: fold Git precedent into an analyzer card when current behavior and its history share the same files, and substitute pattern or integration specialists rather than adding cards. A same-file history question never justifies a standalone precedent locator. Never display a four-card plan and then silently regroup it after the developer responds. Show a runtime-feasible plan covering every question within at most three analysis cards total, then ask **Use scope**, **Revise scope**, or **Stop**. If complete coverage genuinely cannot fit, ask **Revise scope**, **Omit group**, or **Stop** and reject **Use scope** until a feasible revised checkpoint has been displayed and approved. No analysis card may exist before approval of that exact feasible checkpoint.

## Gate adaptive analysis waves

**Use scope authorizes card preparation only.** In the response to **Use scope**, construct and display every complete YAML card for the first analysis wave, ask **Run**, **Edit**, **Omit**, or **Stop**, and end the turn. Do not inspect source, dispatch a child, synthesize findings, prepare a compiled scan, or write an artifact in that response. Only a later **Run** against those displayed cards authorizes their child dispatches and subsequent synthesis.

Choose the smallest roster justified by approved question shape:

- reuse `rpivc-codebase-analyzer` by default for behavior and data flow;
- substitute `rpivc-codebase-pattern-finder` for explicit convention comparisons;
- substitute `rpivc-integration-scanner` for bounded exhaustive connection maps;
- use `rpivc-precedent-locator` only with usable Git history and credible anchors.

External web research is deferred. Record an evidence gap when a question crosses that boundary.

Show every complete card in a wave before asking **Run**, **Edit**, **Omit**, or **Stop**. Dispatch no more than three independent cards per wave and three analysis cards total. One wave never authorizes another. Dependent cards must contain actual returned evidence, use a remaining card slot, and receive a later gate. Custom-agent profiles are fixed: analyzer and pattern finder use Terra/high; integration scanner and precedent locator use Luna/low. Sol/xhigh is available only after a visible reconciliation card is accepted. Before displaying a wave, verify every role, model, and reasoning triple exactly matches this table; do not copy the tracer's Terra/medium profile into analysis cards.

Refresh context before constructing analysis cards and copy the authoritative context fields literally. Validate each complete card separately with `artifact-check.mjs validate-research-card` before displaying it. If context changes after display, redisplay every complete refreshed YAML card and request a new **Run**; a summary of card identifiers is not an approval surface.

The current collaboration runtime permits four direct child threads per parent. The tracer consumes one, so the complete approved scope must fit at most three analysis cards. Show the complete execution plan at the scope checkpoint. If complete coverage needs a fourth card, ask **Revise scope**, **Omit group**, or **Stop** before displaying analysis cards.

Every analysis card uses `dispatch_mode: spawn` and the same supported explicit spawn mapping as the tracer, including `agent_type`, model, reasoning, and no-history context. Copy the full literal text of every assigned approved question into `inputs`; a question number, range, summary, or reference to tracer output is not transport of its clauses. When the spawn-and-wait call is wrapped by `functions.exec`, begin it with `// @exec: {"yield_time_ms": 120000}` but give the inner wait for that same child `timeout_ms: 600000`. The outer yield controls responsiveness; it is not the child's completion deadline. The deferred wait result is a status map keyed by child identifier, not a scalar status. Read `waited.status?.[spawned.agent_id]` and treat it as final when that object owns one of `completed`, `failed`, `cancelled`, or `terminated`; never compare the complete `waited.status` map to those strings. Only if the keyed child state is absent or non-final should the script call the same wait again. Never reread an already final child, treat one wait interval as terminal, spawn a replacement, advance to the next card, or end the turn while that child remains non-final. If the outer call returns `Script running with cell ID ...`, immediately call `functions.wait` with that exact cell identifier until it returns the final spawn-and-wait output. Do not dispatch the next card, inspect source yourself, synthesize, or end the turn while an approved child cell is still running. A dependent card names prior card identifiers in `depends_on`, includes their actual returned evidence, receives a new wave approval, and still spawns a fresh child in one of the three available analysis slots. Never reuse a child, reuse the tracer, hide independent work in another card, or treat an earlier **Run** as authorization for later dependent work.

For every spawn retain safe runtime attestation: displayed-card hash, opaque child-transport hash and byte count, requested runtime settings, task and child identifiers, completion and output hashes, and nested-spawn count. Retain no prompt or output plaintext in attestation and make no exact-equality claim for encrypted payloads.

## Synthesize and checkpoint

The parent synthesizes; children never write the artifact. Require every child to finish with a clause matrix: one row per named clause, the literal clause, Supported/Unsupported/Conflicted status, its finding, and exact evidence or gap. If a terminal child payload omits that required schema or answers a different task, do not silently repair it or spawn a replacement under the same approval. Record the invalid payload as an evidence gap, mark every clause assigned only to that card **Unanswered**, and continue the already-approved turn into synthesis; do not stop at a bare acknowledgement or ask the developer to authorize synthesis again. Treat each approved question as a question, not as evidence that its premise is true. A "how does X" question may be answered "it does not" when current evidence contradicts X. Split every question into its named clauses and map it exactly once to **Answered**, **Partial**, **Conflicted**, or **Unanswered**. **Answered** requires direct evidence for every clause; if even one clause lacks support, use **Partial**, **Conflicted**, or **Unanswered** and name the missing or contrary clause. Never claim a dependent wave ran when the displayed cards all contain `depends_on: []`. Incorporate only exact file-and-line targets returned by children and independently verified against the captured revision; never derive a source line from the artifact's own line number or invent a range for uncited prose. Verify every cited file and line against the captured revision. Use repository-relative labels and absolute clickable targets. Apply this label rule to the compiled scan as well as the artifact; a basename-only label such as `artifact-check.mjs:291-304` is invalid even when its target is correct. One enclosing Markdown code-span pair around the label is presentation-only; after removing it, the label must still exactly equal the repository-relative path and line or range. Treat current code as current truth and Git as precedent. Report facts and constraints, not implementation recipes.

Represent Git precedent with plain code-formatted commit identifiers unless a real existing local file is the link target. Reverify every 40-character identifier used in **Precedents & Lessons** or **Historical Context** with local Git before writing it; the inspector rejects identifiers that do not resolve to commits in the current repository, except the declared external `rpiv_commit` source pin. Never invent filesystem links such as `.git/commit/<sha>`; a commit object is not a local Markdown file target.

Never use a current-file citation to prove that behavior was introduced by, inherited from, or changed in a Git commit. Keep the current behavior and its file citation on one evidence bullet, then put verified history in a separate uncited bullet with the plain commit identifier.

Treat source selection and verdict checks as different evidence. A range that only gathers or stages values cannot prove a later return, hash, comparison, or pass/fail result. Split parser phases into separate bullets: recognizing a coverage snapshot, checking contiguous identifiers and totals, and validating clause rows are distinct claims. Split Markdown-link validation likewise: target/label checks and the later research-width check need their own cited ranges. For runtime attestation, cite the individual `context_mode_matches`, `child_completed`, `child_output_observed`, and `no_child_fanout` check expressions for those verdicts; the earlier code that merely selects dispatch, completion, output, or nested-spawn values does not prove the checks. If one sentence needs evidence from different blocks, make it multiple single-citation bullets.

Ask developer questions only when evidence cannot supply the answer. Ground each question in clickable findings, explain why it matters, and offer two to four concrete choices when choices exist. Batch only independent questions.

Draft a compiled scan of at most 30 lines covering task, scope, layers, key files, integration shape, best matching pattern, precedents, conflicts, gaps, unresolved questions, and clause-complete coverage. Include exactly one canonical line in this form: `- Coverage snapshot: Q1=Answered; Q2=Partial | Totals: Answered=1, Partial=1, Conflicted=0, Unanswered=0`. Follow it with exactly one row per question in this form: `- Q1 — **Answered** — Clauses: <every named clause and its supported finding or explicit gap>`. Use only the four status spellings shown in the snapshot schema. Derive each question status from its worst clause; an Answered row cannot name an unsupported, missing, or unanswered clause. Begin every current-code evidence bullet with its question identifier, for example `- Q1: <one supported behavior>. [path:line](/absolute/path:line)`. Every Answered question must have at least one such labeled evidence bullet. Keep each evidence bullet to one behavior and exactly one current-code citation. If a finding needs two ranges, split it into two independently supported bullets so no rendered line carries two long absolute targets. Before showing the scan, pass the complete draft on standard input to `node .agents/skills/_shared/scripts/artifact-check.mjs prepare-research-scan`. Always use a quoted heredoc with the complete scan and a closing delimiter on its own line; never invoke this command bare. This read-only command validates the coverage projection and Answered-question evidence coverage, canonicalizes every local citation label from its target, checks target existence and line bounds, rejects multiple citations on one line and ranges wider than 15 lines, and returns `normalized_markdown` plus the exact `claim`, `claim_line`, and numbered `source_excerpt` for every citation. A scan-preparation failure does not consume either artifact-inspection invocation: no artifact exists yet, so repair every reported scan citation and rerun preparation until it passes or evidence is unavailable. For a broad range, re-read the numbered source and replace it with the smallest directly supporting range of at most 15 lines; do not merely repeat the same invalid command. Compare every returned `claim` with its `source_excerpt`: each nearby claim must be directly supported by those exact lines. If not, correct the claim or split it into independently supported single-citation bullets and rerun the command. After the JSON preparation passes and every excerpt supports its claim, pass the exact final draft through `node .agents/skills/_shared/scripts/artifact-check.mjs render-research-scan` with another quoted heredoc. This second read-only command repeats deterministic validation and emits only the canonical Markdown, avoiding truncated JSON reconstruction. Present its complete standard output byte-for-byte, then append only the **Write artifact**, **Adjust**, or **Stop** gate; never retype, reconstruct, prefix, or edit the rendered scan. Reuse those verified citations unchanged in the artifact wherever they support the same claim. Write nothing before **Write artifact**.

Scan preparation aggregates every detectable citation defect in one correction set. Repair the complete set in one edit before rerunning; do not fix only its first item and pay one reasoning cycle per citation.

## Write and review one draft artifact

Run `node .agents/skills/_shared/scripts/artifact-path.mjs research <topic>`. The allocator creates the ignored research directory, but not the artifact. Copy its emitted `absolute` path and `common_frontmatter` values literally; never reconstruct the path or filename from `relative`, `created_at`, or the current directory. Then create exactly one new file from the complete template at that exact absolute path. Preserve every template `##` section heading exactly once, even when a section only records that no additional finding, conflict, precedent, or open question exists. In discovery mode, record the repository-relative discovery artifact in `source_artifacts` and link the exact validated absolute discovery-artifact path under Source Feature; a relative link is not sufficient for deterministic lineage inspection. Preserve inherited decisions in Developer Context. In prompt mode, use `source_artifacts: []`, record the original prompt under Source Feature, and state in Developer Context that no discovery decisions were supplied. Before inspection, verify discovery mode has exactly one declared discovery source and prompt mode has none. Also verify that the discovery-mode Source Feature body contains a Markdown link whose target is the exact absolute validated path; prompt mode has no discovery link. Complete question coverage in the Coverage Ledger in both modes.

Before writing, retain the clause-level evidence matrix used for synthesis. Copy the rendered scan's canonical coverage snapshot unchanged into Summary and its Q rows unchanged into Coverage Ledger. Copy the complete rendered scan byte-for-byte, including its heading, snapshot, Q rows, and every evidence line, under Detailed Findings. This is a projection step, not a second synthesis pass: do not change a status, total, clause finding, claim, or citation, and introduce no new current-code claim or citation. In Code References, point to Detailed Findings instead of assembling a new citation table. In Integration Points and Architecture Insights, either copy a complete applicable rendered-scan evidence bullet verbatim or state `No additional finding beyond Detailed Findings.` Do not add uncited current-code prose. Treat the accepted compiled scan as the complete current-code evidence inventory for the artifact: every current-code claim-and-citation pair written into the artifact must be copied from the scan's `normalized_markdown` without changing either the claim or its citation ranges. If the scan lacks direct evidence for a clause, keep that clause Partial or Unanswered instead of adding an unverified citation. Preserve every inherited discovery decision in Developer Context, including negative workflow boundaries such as no automatic successor stage. Pass the exact rendered scan in a quoted heredoc to `node .agents/skills/_shared/scripts/artifact-check.mjs finalize-research <absolute-artifact-path>`. This ordered command first verifies byte-for-byte projection, then normalizes existing local citations, and only then invokes artifact inspection. A projection failure cannot consume an inspection invocation. It rejects current-code citation lines outside the rendered scan and reports `artifact_sha256` only after inspection succeeds. Treat its aggregated errors as one correction set. For an out-of-bounds range, re-read the named target with numbered lines and replace the complete start-end range with verified evidence; never decrement only the end, and never clamp an invalid start to end-of-file. The initial draft has a hard ceiling of two `finalize-research` calls that reach inspection: after the first inspection failure, correct every reported issue once and rerun the same finalizer; if that second inspection fails, stop immediately. Projection-only failures may be repaired and rerun because they never invoke inspection. Never attempt a third inspection. Retain the returned `artifact_sha256` with the draft path, then present its clickable link.

Ask **Accept**, **Revise**, or **Stop** and end the turn. **Revise** updates that same absolute draft path, never allocates another research artifact, reruns `finalize-research` with the exact rendered scan, and shows the unchanged path plus the changed before/after `artifact_sha256` values before repeating the gate. **Accept** freezes the current bytes, creates no sidecar, and invokes no successor. After **Accept**, never modify that artifact.

## Boundaries

- Research is behaviorally read/search/Git-read only outside its one artifact.
- Never fetch, browse the web, edit product code, create dispatch or approval records, commit, push, install, or repair the workflow during use.
- Never create, invoke, route to, or imply `rpivc-design`.
- Never chain automatically. A later stage requires a separate manual invocation.
